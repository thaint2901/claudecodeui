# ADR-0005: Structural cleanup — cycle dissolution, utils split, wire-type single source, full-tier boundaries

**Date:** 2026-08-03
**Status:** accepted
**Deciders:** thaint2901 + Claude phase-6 session

## Context

Four structural debts had accumulated across the backend/frontend module graph, measured 2026-08-03 at `6533049` (the stacked base, phase-5 tip):

1. **15 elementary server-module dependency cycles + 1 frontend cycle** (madge). On the server, 12 of the 15 closed through `server/modules/providers/list/**` CLI/SDK files importing `server/modules/providers/services/**` (all 4 provider files — claude, codex, cursor, opencode — imported all 3 services: `providerAuthService`, `providerModelsService`, `sessionsService`, not just the 6 edges an earlier scan had surfaced), and carried forward ADR-0003's documented crash hazard — the phase-4 eager-registry-capture cycle that had been *defused* (lazy capture) but never *dissolved*. The remaining cycles formed a websocket↔projects↔providers barrel triangle: four services (`session-lock-watcher.service.ts`, `sessions-watcher.service.ts`, `projects-with-sessions-fetch.service.ts`, and `sessions.service.ts`) imported the `websocket` module barrel purely to reach `connectedClients`/`WS_OPEN_STATE` for broadcast, or (in `sessions.service.ts`'s case) `chatRunRegistry.listRunningRuns()` for a read-only query — not a broadcast loop at all. One more cycle closed through `sessions-watcher.service.ts` importing `generateDisplayName` from the `projects` module barrel. On the frontend, `ToolRenderer.tsx → tools/components/index.ts → SubagentContainer.tsx → SubagentTranscriptPanel.tsx → ToolRenderer.tsx` closed through a barrel hop.
2. **`server/shared/utils.ts` god module**: 1,286 LOC, 36 exports, fan-in ~48 files, spanning at least three unrelated domains (HTTP helpers, workspace-path validation, message normalization, JSON I/O, and provider-specific state/skill/session-scan helpers that had never been truly cross-tier). Two exports were dead: `getProviderSessionActiveModelChangesPath` (0 external importers) and `FORBIDDEN_WORKSPACE_PATHS` (0 real importers — only a comment-string match in a test).
3. **Wire types duplicated and incomplete.** `MessageKind`/`NormalizedMessage` were hand-duplicated in `server/shared/types.ts` and `src/stores/useSessionStore.ts`, with field-level drift between the two shapes (server-only `reason`/`toolUseResult`/index signature vs. client-only `exitCode`/`actualSessionId`/`isFinal`, plus `toolResult` optionality and `images` type mismatches). The server emitted `session_lock_state_changed` (`session-lock-watcher.service.ts:121`) that appeared in **no** server-side gateway-kind union — the type was lying about what the server actually sent. The client's `ServerEvent.kind` was a bare `string`, so no exhaustiveness check was possible on the realtime dispatch switch; an unhandled kind silently corrupted the session store (documented CLAUDE.md gotcha).
4. **Boundaries lint covered only `server/modules/*`.** `server/routes/` and root-level `server/*.js`/`*.ts` were unclassified in `boundaries/elements`, so `boundaries/dependencies` skipped them entirely — a deep import from `server/routes/agent.js` straight into `../modules/providers/services/provider-models.service.js` lint clean (verified 2026-07-31). A full re-measure at task time found 13 such deep imports, not the 11 an earlier pass had counted. `browser-use` was the only module with no `index.ts` barrel at all.

## Decision

Dissolve all four debts with three structural mechanisms plus one lint-coverage extension, rather than patching each of the 15+1 cycles individually:

- **Rule A** — `server/modules/providers/list/**` never imports `server/modules/providers/services/**`. All 12 import lines (not the 6 an earlier scan had enumerated) were removed by sibling substitution (each CLI file instantiates its own provider-specific auth/sessions/models class directly, e.g. `new ClaudeProviderAuth()`, instead of routing through the shared service's registry lookup) or extraction of registry-free logic into a new `server/modules/providers/shared/` helper (`is-provider-installed.ts`, `resolve-resume-model.ts`). This retired ADR-0003's Negative-consequences paragraph describing the latent eager-capture cycle across the `provider-models`/`provider-auth`/`sessions` service families: with the closing edge gone, `provider-models.service.ts`'s phase-4 lazy-capture workaround (`(dependencies.resolveProvider ?? providerRegistry.resolveProvider)(provider)`, deferred to call time) reverted to a plain eager capture at module-load time — the hazard the workaround existed to paper over no longer exists, because the registry edge is now one-directional.
- **Rule B** — broadcast inversion via a new leaf module `server/modules/events/` (`setBroadcastHandler(fn)` / `broadcast(message)`, imports nothing from any other module). `websocket/index.ts` registers the real handler at startup (raw-object in, JSON-serialize-once-then-iterate-`connectedClients` exactly as before — wire bytes unchanged); the four `connectedClients`-iterating services switched to `broadcast()`. Review added a per-client try/catch guard inside the shared handler (the original `session-lock-watcher.service.ts` broadcast site had one; the naive shared handler initially did not — a client socket closing mid-send would otherwise abort delivery to every remaining client in that broadcast). Before the handler is registered, `broadcast()` is a silent no-op, matching today's zero-connected-clients behavior.
- **Task 7's seam** — `sessions.service.ts`'s remaining `chatRunRegistry.listRunningRuns()` read was not a broadcast loop, so forcing it through Rule B's handler would have been a category error. Instead, `sessions.service.ts` gained a module-scope `setLiveRunProbe(probe)` / `_resetForTest()` seam (mirroring the events module's own test-reset convention); `websocket/index.ts` registers the real `chatRunRegistry` behind it at startup. This closed the last surviving server cycle.
- **Relocation C** — `generateDisplayName` moved from `modules/projects` into `server/shared/workspace-paths.ts` (landed inside the utils.ts split, since that file's eslint classification was created there); `modules/projects`'s barrel keeps re-exporting it unchanged for external consumers, `sessions-watcher.service.ts` now imports the shared home directly.
- **`server/shared/utils.ts` split by ownership, then deleted, no shim.** Four true cross-tier-shared leaves landed at `server/shared/{http,workspace-paths,messages,json}.ts`; provider-specific slices that were never really shared moved into `server/modules/providers/shared/{active-model-store,skill-files,session-scan,windows-shell}.ts` and `list/opencode/opencode-paths.ts` / `list/cursor/cursor-paths.ts` (the latter, `sanitizeLeafDirectoryName`, homed beside its only two consumers, both in `list/cursor/`, per the brief's implementer-judgment clause). `getProviderSessionActiveModelChangesPath` and `FORBIDDEN_WORKSPACE_PATHS` became non-exported internals instead of moving as public exports, closing the two dead-export findings. All ~48 importer files were repointed in the same change; `utils.ts` was deleted outright — no re-export shim — because this is independent, non-upstream-tracked development and no merge-conflict rationale for a shim survives.
- **`shared/wire-types.ts` at the repo root as the single source.** `MessageKind` (14 members), `GatewayEventKind` (6 members, gaining the previously-undeclared `session_lock_state_changed`), `ServerEventKind = MessageKind | GatewayEventKind`, one reconciled `NormalizedMessage` (union of both tiers' knowledge: server-only `reason?`/top-level `toolUseResult?`/index signature kept; client-only `exitCode?`/`actualSessionId?`/`isFinal?`/`aborted?` promoted to explicit optionals; `toolResult` relaxed to optional with a `| null` union; `images?` typed to the client's narrow shape), plus runtime helpers `assertNever(x: never): never` and `isGatewayEventKind(kind): kind is GatewayEventKind`. `server/shared/types.ts` and `src/stores/useSessionStore.ts` become facades re-exporting from it; `WebSocketContext.tsx` adds `ClientEventKind = ServerEventKind | 'websocket_reconnected'` (the one client-synthesized kind) and re-types `ServerEvent.kind` from `string` to `ClientEventKind`. `useChatRealtimeHandlers.ts`'s two realtime switches were restructured to be exhaustive with `assertNever` in each `default` — switch 1 covers all 6 gateway kinds + `websocket_reconnected`; switch 2 lists the 12 `MessageKind` members TypeScript can still observe at that point (`stream_delta`/`stream_end` are handled and unconditionally returned by two guards above the switch, so TS's own control-flow narrowing excludes them from the switch subject's type — documented inline rather than forced back in, since doing so breaks compilation the other way). Deleting either of those two early returns now fails compilation instead of silently reaching the switch, so the exhaustiveness guarantee is effectively two-layered. Mutation-proven: adding a probe member to either union produces a `TS2345: ... not assignable to parameter of type 'never'` at the relevant `assertNever` call, reverted after confirming.
- **`backend-legacy` boundaries element** covering `server/routes/**`, root `server/*.{js,ts}`, `server/middleware/**`, `server/services/**`, `server/utils/**`, `server/constants/**`, `server/tests/**` — the whole backend is now classified. The 13 measured deep imports (re-measured; an earlier pass had counted 11) were re-pointed through barrels; `browser-use` got its first `index.ts` barrel; 3 provider test files that were deep-importing non-barrel-exported internals (`mapCliOptionsToSDK`, `spawnOpenCode`, etc.) were relocated into their owning module's `tests/` directory instead of leaking those internals through the public barrel. Mutation-proven: temporarily re-adding a deep import in `server/routes/agent.js` reproduces the exact `boundaries/dependencies` error message (`"Cross-module imports must go through that module's barrel file..."`) against the real config; reverted.

**Process note:** `eslint.config.js` was edited twice during this phase (touch #1 for the new shared-file patterns + the `cross-tier-shared` element during the utils split; touch #2 for the `backend-legacy` element). Both edits were pre-authorized by the user for this phase and, because a config-protection hook blocks the implementer from writing to that file directly, both were applied by the controller from a diff the implementer had already validated against a probe copy of the config.

## Alternatives Considered

**(a) Lazy-capture the registry everywhere a service family risked the eager-capture crash, instead of removing the closing import.**
Pros: smaller diff — a defensive wrapper at each risky call site, no need to trace every CLI file's actual usage of each service.
Cons: defuses the crash but does not dissolve the cycle — the module graph stays cyclic, and the hazard's documentation (ADR-0003's Negative-consequences paragraph) has to live forever as a warning to future contributors rather than becoming historical.
Rejected: phase 6 exists specifically to close this gap; papering over it a second time would make ADR-0003's "deferred to phase 6" commitment meaningless.

**(b) Keep `utils.ts` as a re-export shim pointing at the new homes.**
Pros: zero import-site churn — none of the ~48 importer files need to change.
Cons: the god module survives on paper (still 36 re-exports in one file) and in lint config (still needs a `backend-shared-utils` pattern entry covering it); the fan-in-48 signal that made this file worth splitting in the first place stays hidden behind an extra hop instead of being resolved.
Rejected: this is independent, non-upstream-tracked development — there is no merge-conflict-avoidance reason to keep a shim, and keeping one would just relocate the debt instead of retiring it.

**(c) Code-generate the client-side wire types from the server's TypeScript types (or vice versa).**
Pros: guarantees single-sourcing even if the two tiers' tsconfigs ever diverge on what they `include`.
Cons: is machinery built for a problem the repo's existing root `shared/` directory already solves for free — both `tsconfig.json` and `server/tsconfig.json` already `include` root `shared/**`, so a plain shared `.ts` file typechecks on both tiers with zero build-step changes, exactly as `shared/networkHosts.js` already does for host/port helpers.
Rejected: adds a generation step and a new failure mode (stale generated output) to solve something a shared source file already solves today.

**(d) Leave `server/routes/` and root `server/*.js` unclassified in `boundaries/elements`, accept the deep-import gap as a known limitation.**
Pros: no new lint element, no risk of breaking a legacy import pattern nobody has gotten around to cleaning up.
Cons: the measured 11 (re-measured: 13) deep imports persist and regrow — every new route handler is one accidental `import { x } from '../modules/foo/services/bar.service.js'` away from bypassing the module boundary the rest of the backend enforces, and there is no lint signal to catch it.
Rejected: this is exactly the enforcement gap ADR-0003 first flagged for `routes/` and this phase's Sub-goal D exists to close it; leaving it open defeats the point of doing Sub-goals A–C first.

## Consequences

**Positive:**
- Server elementary cycles: 15 → 0 (`npx madge --circular --extensions ts,js --ts-config server/tsconfig.json server/` → `✔ No circular dependency found!`). Frontend: 1 → 1 accepted, documented exception (see below) — no cycle was silently left unaddressed; the survivor was investigated and ruled legitimate.
- ADR-0003's eager-capture cycle hazard is retired, not just documented: the lazy-capture workaround in `provider-models.service.ts` reverted to a plain eager capture because Rule A made the registry edge one-directional.
- The realtime dispatch's kind-exhaustiveness is now a compile-time guarantee: adding a `MessageKind` or `GatewayEventKind` member without a corresponding switch case fails `npm run typecheck` at the relevant `assertNever` call, closing the "unhandled kind corrupts the session store" bug class at the type level instead of relying on code review to catch it.
- Every scorecard line this phase targeted closed: server cycles 15→0; `utils.ts` 1,286 LOC/36 exports/fan-in ~48 → deleted (CodeScene 9.01–10.0 across the 10 new homes); exactly one `MessageKind`/`NormalizedMessage` definition repo-wide; boundaries lint now covers the full backend tier (13 legacy deep imports repointed, `backend-legacy` element added).

**Negative:**
- `sessions.service.ts`'s `_resetForTest()` and the events module's own `_resetForTest()` are test-only exports that exist purely to give tests a way to reset module-scope seam state between cases — a small amount of production-file surface area exists only for testability.
- The legacy tier (`routes/`, root `server/*.js`, `middleware/`, `services/`, `utils/`, `constants/`, `tests/`) is now lint-bound the same way `modules/*` already was: any future edit to a route handler that wants a module internal must go through that module's barrel. This is friction by design — the same discipline the rest of the backend already has — but it is a real constraint on legacy-tier changes that did not exist before this phase.
- Both `eslint.config.js` touches (new shared-file/`cross-tier-shared` patterns; the `backend-legacy` element) were pre-authorized by the user for this phase specifically and applied by the controller rather than the implementing agent, because of the config-protection hook. Future phases touching this file will need the same explicit-permission flow.

**Frontend cycle — accepted exception:** `ToolRenderer.tsx ↔ SubagentContainer.tsx ↔ SubagentTranscriptPanel.tsx` remains a 3-file cycle after the barrel hop that used to mediate it was removed. Investigation (Task 1) found this is not a barrel artifact: `SubagentTranscriptPanel.tsx` renders each tool call inside a subagent's transcript drawer using `ToolRenderer` itself — a direct, intentional recursive UI composition (the same tool renderer draws nested tool calls one level down). Controller ruling: **accepted as a documented exception**, not forced to 0. Breaking it would require a real architecture change — `React.lazy`-splitting one of the three files, or injecting `ToolRenderer` into `SubagentTranscriptPanel` via a render prop — touching all three files' prop contracts or loading semantics for a change that trades working, intentional recursive composition for a topology number, with no behavior or maintainability gain to show for the risk. `npx madge --circular` over `src/` will continue to report exactly this one triad; that is expected, not a regression.
